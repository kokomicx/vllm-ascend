📐 基础概念：Block × Token × Byte

在深入各模型之前，先统一六个贯穿全文的维度符号。KV Cache 本质上是 N 个 Block，每个 Block 包含 B 个 Token，每个 Token 是一段连续的字节。

1. GQA 标准注意力

代表模型：Qwen3 MoE、Llama 系列。每个 token 有 H 个 KV head，每个 head D 维。K 和 V 是两套独立的投影矩阵，但上游把它们交织存放在同一个 tensor 中。

🔵 上游 vLLM — 单 Tensor，K/V 交织

(2, N, B, H, D) FlashAttentionBackend.get_kv_cache_shape()
K 区域 (dim=0, index=0) V 区域 (dim=0, index=1) 1 tensor/层 Reshape: view(dtype).view(2,N,B,H,D)

🔴 vLLM-Ascend — 两个独立 Tensor

(2, N, B, H, D) → 拆为 K:(N,B,H,D) + V:(N,B,H,D) AscendAttentionBackend.get_kv_cache_shape()
k_buffer (独立 int8) v_buffer (独立 int8) 2 tensors/层 Reshape: k.view(N,B,H,D) + v.view(N,B,H,D)
🔑 关键差异：
  • 上游：kv_cache[0]=K, kv_cache[1]=V，同一块物理内存内通过指针偏移区分 → 1 个 tensor
  • Ascend：NPU DMA 不接受 stride → K 和 V 必须各自独立分配 → 2 个 tensor
  • 信息丢失：无。Backend 返回的 (2,N,B,H,D) 语义完整，model_runner 仅机械拆分 dim=0。

2. 标准 MLA DeepSeek V3.1

MLA 将多头 KV 压缩为一个 latent vector，num_kv_heads=1（单虚拟头）。head_size=576 实际是 kv_lora(512) + k_rope(64) 在同一维度的拼接——这是 MLA 存储的核心：两个语义独立的组件在最后一个维度平面存放。

🔵 上游 vLLM — 单 Tensor，平面拼接

(N, B, 576) MLACommonBackend.get_kv_cache_shape()
kv_lora (512) k_rope (64) 1 tensor/层 Reshape: view(N,B,576) 1行

🔴 vLLM-Ascend — 两个独立 Tensor

(N, B, 1, 576) → 查 layer 拆为 (N,B,1,512) + (N,B,1,64) AscendMLABackend.get_kv_cache_shape()
k_cache (nope) v_cache (rope) 2 tensors/层 ⚠ model_runner 查 layer 获取拆分点
🔑 关键差异：
  • 上游：576=512+64，但 model_runner 不知道也不关心。拿到 (N,B,576) 直接 view，kernel 内部 offset 切分。
  • Ascend：Backend 返回 (N,B,1,576) → model_runner 绕过 Backend 直接查 attention layer 获取 kv_lora_rank=512 和 qk_rope_head_dim=64 → 拆为两个独立 tensor。
  • 差距：★★ — head_size=576 的拆分信息丢失。Backend 的 static method 接口物理上拿不到这些参数。

3. Sparse MLA DeepSeek V3.2 · bf16 + fp8 C8

DS V3.2 在标准 MLA 基础上增加了 Sparse Attention Indexer——需要额外存储 indexer 的 K。上游用 656B 的 opaque blob（kernel 私有格式）封装一切；Ascend 拆为 3~4 个独立 tensor，且 tensor 数量 非单调（bf16→3, C8 A3→4, C8 A5→3）。

🔵 上游 vLLM — 单 Tensor，656B Opaque Blob

(N, B, 656) ← 最后一维是字节布局，不是 head_size！ FlashMLASparseBackend.get_kv_cache_shape()
NoPE fp8 (512B) Scale fp32 (16B) RoPE bf16 (128B) 1 tensor/层 Reshape: view(uint8) 1行

🔴 vLLM-Ascend — 3~4 个独立 Tensor，非单调

(N, B, 1, 576) → 拆为 3 (bf16) 或 4 (C8 A3) 或 3 (C8 A5) AscendSFABackend.get_kv_cache_shape()
kv_lora k_rope indexer K indexer Scale ⚠ 3~4 tensors/层
非单调：bf16→3, C8 A3→4, C8 A5→3。sparse_kv_cache_ratio 提供 split 比例，但也在 Spec 上而不在 Backend 上。
🔑 关键差异：
  • 上游：Backend 返回 (N,B,656) 而非 (N,B,576)——magic number 编码精度信息。model_runner 视其为 opaque blob。
  • Ascend：Backend 返回 (N,B,1,576)——和标准 MLA 完全一样。tensor 数量和形状全由 model_runner 重建。
  • 差距：★★★ — 1/N 信息问题达到极致：1 个返回 shape vs 3~4 个实际 tensor，且组合随精度和硬件变化。

4. Compress MLA DeepSeek V4

DS V4 引入时间压缩（compress_ratio）和独立 Indexer。上游用 584B 私有格式；Ascend 是"复杂度倒挂"的典型——Allocate 最简单（1 个 int8 buffer），Reshape 最复杂（as_strided 承载 3 种语义叠加视图）。

🔵 上游 vLLM — 单 Tensor，584B 私有格式

(N, B, 584) ← V3.2=656 vs V4=584，不同 Backend 子类，不同 magic number DeepseekV4FlashMLASparseBackend.get_kv_cache_shape()
NoPE fp8 (448B) RoPE bf16 (128B) Scale ue8m0 (8B) 1 tensor/层 Reshape: view(uint8) 1行

🔴 vLLM-Ascend — 1 Buffer + as_strided 多重视图

(N, B, 1, head_size) + get_scale_shape() → 1 buffer → 2~3 views AscendDSABackend.get_kv_cache_shape() + get_scale_shape()
view[0]: indexer K view[1]: indexer Scale view[2]: full overlay (A5) ⚠ "复杂度倒挂"
🔑 关键差异：
  • 上游：584 字节私有格式。V3.2=656 vs V4=584——Backend 子类不同，magic number 不同，model_runner 不变。
  • Ascend：1 个 int8 buffer 分配最简单（≈上游），但 as_strided 承载 compress_ratio / KV merge / epilog kernel overlay 三种语义。
  • 差距：★★★★ — "复杂度倒挂"。应该由 Layout 层告诉 reshape "这块 buffer 怎么解读"，而不是 reshape 自己推导。

5. Hybrid Qwen3.5 · Attention + Mamba

Qwen3.5 混合了标准 Attention 和 Mamba (Linear Attention)，两者共享同一块物理 buffer。上游通过 shared_by + as_strided 零拷贝解决；Ascend 需要 manual padding strip + K/V offset 计算。唯一复用上游 Spec 而不需要 Ascend 万能类的模型，但差距最大。

🔵 上游 vLLM — 两种 Spec 自然共存

FullAttentionSpec → (2,N,B,H,D) · MambaSpec → own shape shared_by 机制：多层共享 1 个物理 buffer
Attn 层用 K/V 区域 Mamba 层用 conv+ssm 1 shared buffer Reshape: as_strided_ 零拷贝重排 ~5行

🔴 vLLM-Ascend — Manual Padding + K/V Offset

复用上游 Spec + page_size_padded → (2,N,B,4,256) AscendAttentionBackend — 但 model_runner 需要 ~100 行 hybrid 专用逻辑
conv_padding strip 手动 K offset 手动 V offset ⚠ 差距 ★★★★★
🔑 关键差异：
  • 上游：FullAttentionSpec + MambaSpec 两种原生类型 → shared_by 统一管理 → as_strided_ 零拷贝重排 → ~5 行。
  • Ascend：复用上游 Spec（无需 AscendMLAAttentionSpec！）但需要 page_size_padded + padding strip + 手动 K/V offset → ~100 行。
  • 核心启示：差距根本不在 Spec，而在 Layout 抽象缺失。Hybrid 的 attention 和 mamba 各自需要不同布局，但没有任何一层告诉 reshape"这块 buffer 怎么划分"。

🔍 三个根本源头

🔴 硬件约束
NPU 算子不支持 stride 访问
→ DMA Engine 只接受 {base_addr, length}
→ Host 侧必须预拆分为连续 tensor
→ 涵盖 K/V 分离、Sparse 多 tensor
Compress 交织、A3/A5 差异
🟣 Spec 设计
类型不编码语义
→ 5 种 MLA 变体 → 1 个 AscendMLAAttentionSpec
→ isinstance() 无区分力
→ 下游用 if-else 恢复丢失的类型信息
→ 精度 × 硬件 × 模型 组合爆炸
🟠 接口缺陷
get_kv_cache_shape() 单返回值
→ tuple[int,...] 无法表达多 tensor 布局
→ 只能返回 1/N 参考 shape
→ 剩余 N-1/N 泄漏到 model_runner
→ 接口假设 "1 attention = 1 tensor"
💡 三者互相放大：
如果 NPU 支持 stride → Spec 设计缺陷影响小得多（不需要多 tensor 拆分）
如果 Spec 用了正确的子类 → 硬件约束的后果更可控（split 逻辑封装在子类里）
如果接口返回完整 Layout → 硬件约束的细节不会泄漏到 model_runner
三者叠加 → model_runner ~600 行、15+ if-else 分支。

📐 上游核心原则 vs Ascend 现状

🔵 上游 vLLM — 三条原则
1. Backend 说了算 — KV Cache shape 的唯一决定者。get_kv_cache_shape() 返回完整可用 shape。tensor 数量、K/V 存储方式——全部由 Backend 封装。

2. 单 Tensor 原则 — 所有模型类型都产生 1 个 tensor/层。MLA 的 kv_lora+k_rope 在同一 tensor 内，kernel 自己 offset。Mamba 的 1 buffer → N 个 as_strided 零拷贝视图。

3. model_runner 零感知 — 不检查 layer_type。不判断 use_sparse/C8/A5/A3。拿到 Spec→shape→分配→reshape→结束。~60 行，0 分支。
🔴 vLLM-Ascend — 三条偏离
1. Backend 只答 1/N — Backend 返回 (N,B,1,576) 作为"参考 shape"。Sparse MLA 需要 3~4 个独立 tensor，但接口只返回 1 个等价 shape。剩余泄漏到 model_runner。

2. 多 Tensor 原则（被迫） — NPU 不支持 stride → K/V 必须物理分离 → Sparse MLA 必须 host 预拆分 → Compress 需要 as_strided 承载模型语义。

3. model_runner 被迫感知一切 — 检查 use_sparse / compress / hybrid / C8 / A5 / A3 / cache_only → ~600 行，15+ if-else。每新模型改 3~5 处。
